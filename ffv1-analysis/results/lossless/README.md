# Lossless formats: regular_batch_060

Generated by `scripts/image_formats.py` from the analysis' report (`cargo run --release`, [`images.json`](../images.json)); do not edit. Part of [the comparison of the image formats](../README.md), whose charts show these formats next to the lossy ones.

These formats keep the frames exactly as dav1d decodes them, 8-bit YUV 4:2:0, BT.709 in limited range, with no conversion, like FFV1, the reference they are written from. After writing each image, the analysis reads it back and checks it byte for byte against its frame, and stops if one differs: every one of the 60 images of every format here is exact. They differ from FFV1 only in size and speed.

Converting from FFV1 is reading the FFV1 frame (45 ms) and writing the image. Each format's README has its charts, frame by frame: the size, the conversion, encoding and decoding time of each image, all the images against FFV1.

## What it shows

- **Raw I420**: 50.6 MiB per image, 10.4x larger than FFV1; converting an image from FFV1 takes 49 ms, reading it back 3 ms (16.4x faster than FFV1).
- **TIFF (YCbCr 4:2:0)**: 14.3 MiB per image, 2.9x larger than FFV1; converting an image from FFV1 takes 1043 ms, reading it back 71 ms (1.6x slower than FFV1).
- **AVIF (lossless)**: 6.4 MiB per image, 1.3x larger than FFV1; converting an image from FFV1 takes 595 ms, reading it back 539 ms (12.1x slower than FFV1).
- **Raw's 50.6 MiB frames**: a frame is over the 50 MiB a message may carry to mosaicod (its default decode limit), and served back to a client it comes in one `DoGet` message, which may carry up to 512 MiB. The compressed formats are well within both.
- Raw I420's first images take longer to encode (7, 7 ms, against a median of 4 ms): a warm-up, included in the means.
